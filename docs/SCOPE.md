# Scope — what "finished" means for Forma

Status: proposed 2026-07-26. Owner decision pending (see §6).
Instrument: [`scripts/presentable.mjs`](../scripts/presentable.mjs). Measured against `haben`
(a real, foreign, 53-package Go + React repo) and against Forma's own model.

Forma shipped to npm at 0.6.0 and is public. It reached stage 4 without passing stage 3 —
*"it works for someone who is not you, on a machine that is not yours."* The mechanical half of
stage 3 is done and provable: published with provenance, installed and run on two virgin repos,
zero runtime deps, CI green. The half that is missing is the one a stranger meets in their first
five minutes. This document draws the line around that, and nothing else.

---

## 1. The definition of finished

> **Forma is finished when the demo linked from the README is generated by Forma from a real
> repository that is not Forma, and on that model `node scripts/presentable.mjs <model>` exits 0
> and `forma check` exits 0 at the same commit — and on that same repository, a bare
> `forma init` seeds a context that names its actors and either seeds every stack it detected or
> prints the ones it skipped with the exact `leafSources` to paste.**

`presentable.mjs` is four predicates, measured exactly as a reader sees them on screen:

| # | Predicate | Why it is the bar |
|---|---|---|
| 1 | context carries ≥1 external actor besides the system | slide one of any architecture talk is *who touches this*; one lone box is not a big picture |
| 2 | no drawn level exceeds 24 boxes | above that the viewer's own legibility floor and the reader's both fail |
| 3 | every box carries prose, not a file count | `6 source files.` is what the code counted, not what the part does |
| 4 | every drawn level with >1 box draws ≥1 edge | boxes without arrows are a bulleted list in rectangles, not architecture |

Two people running that command on the same model get the same verdict. That is the whole point
of writing it as a command instead of a paragraph.

**The second half of the sentence is not decoration.** Predicates 1, 2 and 3 can all be made to
pass by hand-curating the topology — I did exactly that on `haben` in 89 s of scripted editing.
A demo Luca hand-built is not evidence that Forma works for someone who is not Luca; it is the
stage-3 skip happening a second time. So the definition also constrains what a *bare* `init`
produces, checkable by anyone with a fresh clone: count the context nodes in the topology JSON,
and look for either a container whose `tech` is not the dominant language or the stderr line
naming what was skipped. That clause is what makes #33 and #34 load-bearing rather than optional.

**Today nothing passes it** — including the demo the README currently links:

```
$ node scripts/presentable.mjs docs/architecture/c4-model.json     # Forma on Forma
PASS context carries at least one external actor besides the system  (6 box(es) at context)
PASS no drawn level exceeds 24 boxes  (widest=13)
PASS every box carries prose, not a file count  (bare=0)
FAIL every drawn level with more than one box draws at least one edge  (edges per screen=5,5,0,0,0)

$ node scripts/presentable.mjs <haben-clone>/docs/architecture/c4-model.json   # foreign repo, uncurated
FAIL context carries at least one external actor besides the system  (1 box(es) at context)
FAIL no drawn level exceeds 24 boxes  (widest=53)
FAIL every box carries prose, not a file count  (bare=28)
PASS every drawn level with more than one box draws at least one edge  (edges per screen=189)
```

## 2. What was measured, and how

Probe: `git clone --local` of `haben` (53 Go packages, a React frontend, a governed
`docs/FEATURE_MATRIX.md`), then `forma init` → `forma gen` → `forma serve`, then the viewer
driven by Playwright and read as a screenshot. Not the test suite — the picture.

**The engine delivers.** `init` 0.06 s. `gen` derives **189 container edges from Go `import`
blocks**, and joins **39 capability rows to 29 nodes, describing 25 verbatim** from the feature
matrix, with `verify.source` naming the document and the tally. Drilled into a curated domain,
the result is a slide you would actually project: eleven boxes, real arrows with reference
counts, a sentence per box taken from a document, a percentage per box that `forma check`
re-derives and will fail on if the document stops supporting it. **That part is done. It is not
in this scope, and it does not get relitigated.**

**Three gaps sit between that and a stranger.**

**(a) The first screen is one empty box.** `init` seeds exactly one context node whose
description is `"<repo> — drill for containers."`, and no actors. The reader's first screen —
the one that decides whether they keep looking — is blank. The README says "best-effort; then
curate", which is honest, but a stranger has no idea that the curation is *mandatory* for the
first screen to say anything.

**(b) Grouping is required, and it silently costs the graph.** On 53 containers the level is a
7×8 wall; 0.8.0 raised the type from 3.24 px to 10.9 px, and its own commit message records that
**85–91 % of the 189 arrows cross boxes that are not their endpoints at any grid shape — "the
layout cannot solve it, only draw fewer."** Drawing fewer means grouping the packages into
domains, and grouping works: I grouped 53 into 6 domains plus the frontend, and the context and
container levels became genuinely presentable. But:

- setting the intuitive `kind: "component"` on a grouped package drops **189 edges to 13, with
  no warning** — the Go adapter matches on `kind === 'container'`. Keeping `kind: "container"`
  and moving only `level`/`parent` preserves all 189. Nothing in the README, `--help`, or the
  `init` output says this;
- and even done correctly, the domain level **draws zero arrows and tallies `2/7` instead of the
  25 packages that carry a verdict** — edges and status do not roll up to the box that contains
  them. Predicates 1–3 pass on the curated model; predicate 4 fails at exactly the level a
  stakeholder is shown.

**(c) A two-stack product shows one stack.** `init` detects a single dominant language. On
`haben` it seeded 53 Go packages and omitted `frontend/` — the entire React application the
family actually uses — from the model. `--include frontend/src` is named in an `init` error
message and has no effect on a Go repo (verified). The second stack is reachable only by
hand-writing a `leafSources` entry.

**Cost of the curation, measured.** Editing the topology took 89 s of scripted work; choosing
six honest domain names and writing their descriptions is the real cost, ~30–60 min of someone
who knows the repo. That is an acceptable price — but only once it is written down, and only
once it does not silently destroy the graph.

## 3. Inside the boundary

Four issues, milestone **`confine — sostituire PowerPoint`**. Each closes one measurable gap.

| Issue | Gap | Closed when |
|---|---|---|
| #32 | grouping loses the graph and the tally | a grouping box draws its children's edges and reports their statuses; a curation that would drop edges says so instead of passing quietly |
| #33 | the first screen is one empty box | `init` seeds the actors and `gen` says so while the context has none |
| #34 | a two-stack repo shows one stack | `init` on `haben` seeds the frontend too, or names it and prints the exact `leafSources` to add |
| #35 | the public demo is Forma demoing on Forma | the README's demo is generated from a foreign repo and `presentable.mjs` + `forma check` both exit 0 on it |

#35 is the closing act, but it is **not sufficient on its own**: §1's second clause is graded on
the same repo with a bare `init`, and only #33 and #34 can make it pass. The milestone is done
when all four are, not when #35 is.

## 4. Outside the boundary

Named, so it stops being reopened:

- **Every new engine capability** — no new language adapter, no new command, no new source kind.
- **`PLAN.md` phase 3** (untracked draft at the repo root, dated today): removing `--from-docs`,
  un-exporting `holesIn` / `BEGIN` / `END`, the dead `HERE` / `basename`, the `LAUNCH.md`
  reference to a `GITHUB_ABOUT.md` that does not exist. All real, none visible to any user, none
  of it changes whether Forma replaces a slide deck. Do them when someone trips over them.
- **The `progress 100% 25/53` headline.** The denominator choice is argued in a comment at
  `lib/viewer/c4-hologram.html:236` and the render does show `25/53`. Decided. Not reopened.
- **Promotion, social preview, launch copy.**
- **`status-plan.json`**, the writable channel orphaned by the branch closed in #27 — `docmap`
  covers the need.

## 5. Estimate — 5 to 7 person-days

Built bottom-up, not guessed:

| Work | Days | Reasoning |
|---|---|---|
| #32 roll-up of edges + tally to the grouping box, plus the silent-loss warning | 2.0 | edge roll-up is viewer-side (map each endpoint to its ancestor among the drawn siblings, dedupe, sum counts) ≈ 1 d with fixtures; the tally roll-up shares that walk ≈ 0.5 d; the warning ≈ 0.5 d |
| #33 context seeding | 0.5 | `init` writes two placeholder actors and one edge; `gen` prints a line while they are unnamed |
| #34 second stack in `init` | 2.0 | the only structural one: `init` assumes a single `ext[0]` from `bin` to `leafSources`. Widening that touches the language detection, the skip policy and the id claim |
| #35 the foreign demo + Pages + README | 1.5 | ~1 h of honest curation content, the rest is pointing the Pages workflow at a model generated elsewhere and rewriting the README paragraph |
| release 0.9.0 | 0.5 | changelog, tag, npm |

**Total 6.5 d, quoted as 5–7.** Wall clock is likely shorter: 0.7.0 → 0.8.0 landed inside a
single day on 2026-07-26. The estimate is effort, not calendar.

## 6. Decisions that stay with the owner

1. **May the public demo be `haben`?** All three candidate repos (`haben`, `arbiter`,
   `coach-system`) are private, so any choice publishes one private repo's *structure* — package
   names and capability sentences, never data — permanently, in this public repo. `haben` is the
   default because it is the only one with a governed feature matrix, which is what makes the
   boxes read as product instead of code. **Yes / no.** (No ⇒ you name the repo.)
2. **0.8.0 is committed on `main` and unpublished** (npm is still at 0.7.2), and it carries a
   BREAKING Go change: a package is now one node, 107 → 54. **Does it ship now, or fold into the
   0.9.0 that closes this boundary?** **Now / fold.**
3. **Does the boundary exclude every new engine capability — no new language, no new command?**
   **Yes / no.**
4. **Do the dead-code and `--from-docs` cleanups stay outside, done only if someone trips over
   them?** **Yes / no.**

## 7. After the boundary

Forma moves to stage 5, *maintained*: it takes bug reports and dependency-free security fixes,
and nothing else without a new scope document replacing this one.
